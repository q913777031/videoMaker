# 黑金无旁白科普短片：制作流程

引擎在 `kepu/`，每条片子是 `topics/<slug>/` 下的一个题材目录。样板片是 `topics/night/`（《为什么一到晚上，就觉得自己的人生不行了》），交付物见 `deliverables/night_rumination/`。

## 0. 输入判断

| 用户给了什么 | 做法 |
|---|---|
| 完整提示词（结构同 `prompt_template.md`，含分镜、白名单、参考资料） | 直接执行第 1–8 步，不问风格 |
| 只有题目、文献或大意 | 先按 `prompt_template.md` 起草完整提示词，保存为 `plans/<slug>.md`。事实白名单只写已核验的内容；核验不了的写“未核验”。把草稿交给用户确认后再渲染 |

题材内容（字幕原文、角标、事实边界、参考资料、封面和发布文案）一律来自提示词。字幕逐字照录，不自行加字幕。

## 1. 环境

```bash
pip install -r requirements.txt
python3 -c "import skia" || apt-get install -y libegl1      # skia 需要 libEGL
python3 fetch_assets.py --fonts-only                        # 思源宋体/黑体，约 80MB，不入库
```

背景音乐按 `CLAUDE.md` 的约定，一律用 `music/bgm.m4a`；构建时依次查找 `./bgm.m4a`、`./music/bgm.m4a`、`./assets/bgm.m4a`。用户说“已上传到根目录”但根目录下没有时，先 `git fetch` 并检查各分支上的 `music/bgm.m4a`，把实际使用的路径告诉用户。原曲缺失时只出“待配乐预览”，绝不合成替代配乐。

## 2. 事实核验

- 按提示词核验文献的书目信息和摘要。这个环境常常访问不了 PubMed 和 Crossref：访问失败就如实写进 `references.txt` 的“核验范围”，并在交付说明中写明“依据所附摘要范围制作，未额外核验”。
- 片中只用白名单里的结论：研究段用“文献归纳示意”，不拍虚构实验、不画带刻度的假数据图。年份写成发表年份。

## 3. 建题材目录

```bash
cp -r topics/_template topics/<slug>
```

- `shots.py`：每镜写一个 `Shot(no, "主字幕／第二行", "角标", [Cue(...)], extra=, credit=)`。
  - 角标只用“情境演绎 / 研究示意 / 机制示意 / 反思练习 / 生活提示 / 参考资料”。
  - `Cue(键, 镜头内基准秒, 音色, 视觉撞击动作描述, 增益, snap=, window=)`。音色键见 `kepu.config.SOUNDS`，一种关键动作只对应一种音色。`snap=False` 用于沙锤这类移动动作；音色为空串表示“无新增音效”（思考窗口）。
  - 研究段、陌生术语加 `extra=1.0`；片尾来源卡用 `credit=True`，其 Cue 带 `window=(-0.02, 0.45)`。
- `__init__.py`：片名、封面主副标题、发布标题、话题、`REFERENCES` 全文、封面主体 `_cover`。需要跨镜头承接运动相位时写 `post_cues`（参考 `topics/night/__init__.py`）。

## 4. 写场景（`scenes.py`）

- 签名 `(c, t, D, cue, view)`：舞台为 1000×1000 单位，`D` 是本镜实际时长（贴拍后会变），`view` 是可见舞台范围，背景要铺满它。
- 主字幕、角标、来源卡都由引擎绘制，场景里**不画字**。
- 先复用 `kepu/props.py`：床边投影、透视桌面与文件、卡片城市、环形轨道、综述书本、绕圈步行与门、事实/行动格、反思纸、夜窗。基元（纸卡、阴影、灯光、人物骨架与姿势）在 `kepu/draw.py`。新道具若能复用，就加进 `props.py`。
- 人物用 `d.figure` 的原创中性上班族（深色衣服、领口一道金线、无面部）。全片外形一致，情绪只靠姿势和物体变化表达。
- **撞击动作的同步规则**（实测踩过的坑）：
  - 撞击时刻只读 `cue["键"]`，不写死秒数。
  - 撞击帧必须是画面变化最大的一帧：落定动作用 `ease_in` 收在 `cue` 上；瞬时效果用 `d.pulse(t, cue)`；需要“从撞击帧开始”的动作用 `prog(t, cue - F, …)`。
  - 不要让 `ease_io` 或 `ease_out` 的主体运动跨在撞击点之前；不要在撞击前做大面积的透明度渐变。
  - 暗色物体落定时，配一个光晕脉冲，否则帧差不明显。
- 每 4–8 秒至少有一个有解释作用的物体变化；字幕阅读期间文字不漂浮、不缩放。

## 5. 抽帧检查（快，约 0.03 秒/帧）

```bash
python3 -m kepu.build --topic <slug> --stills 0.1,9,33,57,87    # 输出 out/<slug>/stills.png，横竖屏各一行
```

用 Read 查看拼图：字幕是否溢出、关键物体是否落在安全区（竖屏 x 90–920、y 180–1580；横屏四边各留 80）、人物与道具是否穿帮。

## 6. 构建成片

```bash
python3 -m kepu.build --topic <slug>      # 4 核约 4 分钟；--only vertical 只出一版；--covers-only 只出封面
```

卡点规则（引擎自动执行，交付时如实转述）：

- 节拍网格：在包络自相关附近细扫拍长和相位；每 15 秒窗口统计网格与实际强起音的中位偏差，**超过 15 ms 就报错**，不在速度不稳的曲子上硬套网格。
- 小节重拍（第 1 拍）：四个拍位中“低频能量 + 和声变化”得分最高的拍位。起音最强的拍位不一定是重拍，可能是反拍军鼓，记作“次强拍”。
- 撞击事件：依次尝试 ±1.1 s 内的重拍、±1.7 s 内的重拍、±0.6 s 内的第 3 拍、±0.3 s 内的任意拍，都没有就保持叙事位置并标为柔和动作。避开镜头开头 0.8 s；同一镜内后一个事件至少晚 0.35 s。
- 镜头边界：依次尝试 ±1.0 s 内的段落起点重拍、±0.45 s 内的重拍、±0.45 s 内的第 3 拍、±0.3 s 内的任意拍。每次移动都复核两侧阅读窗口（时长 ≥ 5 s，且 时长 - 0.8 ≥ 需求）。
- 音效起音放在节拍的精确时刻，画面撞击放在最近帧（偏差 ≤ 半帧）。原曲在该拍低频占比 > 0.3 时低音鼓减半，> 0.5 时取消。
- 原曲时长在目标 ±3 s 内整曲使用；更长则选段；更短直接报错（不循环、不拉伸）。曲尾从最后 2–3.5 s 内的重拍起做余弦淡出。混音向 -16 LUFS-I 靠拢，真峰值 ≤ -1 dBTP，用平滑限幅，不削波。

## 7. 验收（读 `out/<slug>/verify_report.json`，逐项对照）

| 项 | 合格线 |
|---|---|
| `ffprobe` | 两版都是 H.264、yuv420p、30/1 fps，帧数 = 总长 × 30，带 AAC 48 kHz 音轨 |
| `blackdetect` | 无（片尾 0.4 s 淡出不算） |
| `sfx_onset_check` | `diff_frames` 全为 0；`vs_beat_ms` 接近 0 |
| `visual_hits` | 全部 \|diff_frames\| ≤ 1；超出就回到第 4 步改撞击动画 |
| `reading` | 全部 `ok: true` |
| `mix_measured` | 约 -16 LUFS-I，真峰值 ≤ -1 dBTP |
| `check/*.png` | 用 Read 查看解码帧：无错字、遮挡、溢出 |

`cue_table.csv` 中置信度为“低”的事件（重拍上起音很弱），要在交付说明里点名，请用户试听复核。

## 8. 交付

1. `cp -r out/<slug> deliverables/<slug>/`，写 `DELIVERY.md`，分“已渲染 / 已核验 / 未完成”三段，可参考 `deliverables/night_rumination/DELIVERY.md`。数值一律来自 `verify_report.json`，不把目标值写成实测值。
2. 写明没做人工试听、没在手机上实听。原曲是否含人声也无法确认。
3. 提交并推送；用 SendUserFile 发送两个 MP4、`cue_table.csv` 和 `DELIVERY.md`。
4. 回复用户时，先给结论，再按“原曲分析 / 卡点 / 需要你确认”三段说明，列出不在重拍上的撞击事件及原因。
